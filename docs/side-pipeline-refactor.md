# 普通横版分层流程的代码整理

本次整理以 `basic-side-v1` 的参考图、分层、绑定、待机/走路和审核为主。
保持动作、搜索范围、检查阈值、文件格式和原有拒绝条件，不改变生产能力范围。

## 实现

- `workflow_assets.JobAssets` 在一次命令内复用抠图结果及素材哈希。参考图审核的文件字节哈希
  与视觉审核的 PNG 像素哈希分别计算。输入数组只读；每个新命令建立新快照。
- 参考图提交与后续检查复用 `validate_reference_review` 和 `validate_job_reference`。
  提交失败时撤销旧审核、保留阶段与重试历史的原有行为未移入缓存。
- `sprite_anim.frame_checks.FrameContext` 在一个动作的质检期间复用姿势、布料位置和最终网格。
  `puppet_qa.check_clips` 按原顺序执行独立检查，保持原报告字段和故障定位。
  网格缓存上限 32 MiB、128 条；姿势与布料记录各最多 128 帧。容量不足时重新计算。
  缓存键包含帧和画布几何；不共享原始取景网格、最终图像遮罩、检查结论或其他动作的结果。
  渲染、独立 QA 命令、最终交付门禁仍分别运行。
- `RegistrationScore` 为每个搜索尺度预计算参考图 RGB/alpha、原图层像素数和 PIL 图像。
  保留候选的计算顺序、浮点精度及代价公式；原配准搜索缓存继续按代码与输入内容失效。
- `review_support` 统一 GIF 时长、分组及姿势覆盖数据，视觉生成与验证共用细节审查清单。
  单次审查图构建使用 32 MiB 的输入图片缓存，返回副本以隔离绘图操作；构建结束释放。
  `record`、`--check` 和审核素材哈希不使用这个缓存。构建中的相同素材哈希扫描由两遍减为一遍。
- 从 `_bind` 提取图层配准与四肢测量阶段，从生成入口提取渲染、引擎文件、特效和连接证据。
  `_bind` 从 376 行缩到 278 行，生成入口 `main` 从 256 行缩到 176 行。

## 等价性与收益证据

使用仓库原有合成测试人物的高、矮两种体型，在同一输出路径、相同 Python 哈希种子下，
对比 `d05957f` 和本次源码。绑定阶段对已对齐素材使用相同的 identity registration 测试夹具；
这项比较不替代真实 AI 美术、配准搜索或用户动态验收。

- 两套实际导出的待机/走路、图集、引擎文件、数值报告、审查 PNG/GIF、清单及审核 ID，
  分别 88、87 个文件，逐字节一致。两个体型的绑定图与配置也在独立目录比对中保持一致。
- 256px、8fps 的 7 帧合成走路：六项身体检查加遮挡候选检查，共 39 次网格生成降到 7 次。
  故障列表、连接/颈部/手部测量及遮挡候选相同；该例缓存网格占 298816 字节。
- 同一合成任务的绑定前复查由 20 次抠图降到 10 次，即参考图、七层美术和两个提示各一次。
- 单独对同一合成躯干运行完整配准搜索：原实现执行 20257 次评分，新实现只准备 4 份尺度数据；
  搜索仍评估原有候选，最终全部配准参数和误差逐值一致。
- 新增故障注入验证缓存中的断连仍定位到原动作/帧；小容量回退、不同画布尺度、错误采样范围、
  跨命令换图、图片缓存隔离，以及预计算评分与原评分逐值一致均有测试。

以上是计算量与等价性证据，不能据此宣称完整生成速度提高固定倍数。
本轮并发测试下的端到端计时有明显调度波动，未将它作为稳定的产品性能指标。

## 旧回归基准的核对

首次对仓库旧 `dev/baseline.json` 运行严格比较得到 0 状态回退、116 处像素/帧变化、
102 处数值漂移，严格命令退出 1。旧基准最后更新于 `7902cf6`，早于本次改动前的 `d05957f`。
保留该次失败记录，并从独立归档的 `d05957f` 源码重新生成全部 26 套。

改前与改后的 26 套、1124 个动作的快照逐值一致，完整 `qa_report.json` 也全部一致。
改前版本自身对旧基准产生完全相同的 116/102 差异。因此先以**改前版本的输出**修复陈旧基准，
作为独立提交；未用优化后结果掩盖新差异，没有删动作、改阈值或删失败项。
修复后，改前与改后两边的严格比较均为 0 regressions、0 changed、0 drifted。
