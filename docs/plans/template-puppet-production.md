# 先定义完整部件，再绘制外观的制作方案

状态：2026-11-02 提案，尚未实现或通过真实美术验收。本文不更改现有默认入口，不修改两个失败案例的结论，不授权重新开始旧任务的生成计数。

## 1. 推荐路线与明确代价

首版采用受限的分层人偶模板：程序提供完整的部件几何、关节和遮挡顺序，AI 根据角色图绘制这些部件的外观，程序组装，再用现有骨骼生成动画。

用户只提供角色图，代理负责外观分析、模板选择、固定提示词、生成、审核、修复记录及预览。用户看身份适配稿和走路效果，不需要写提示词、描掩码或标关节。开发模板时制定通用规则，不逐角色手调。

原图是身份和设计参考。最终交付是为动画重新制作的角色，允许经过说明和认可的结构适配；不承诺原画每个像素、褶皱和轮廓都保留。首版继续采用已约定的短发、短衣、侧视、单手剑/空手。长袍、长马尾、宽袖、复杂盔甲不能在未验证时混入该能力；也不能静默删掉标志性设计。

若要求任意原图、原设计完全保留、无人修图、始终一次成功，当前技术和已验证代码无法提供这个承诺。本方案通过限制输入及制作规格提高可交付性，仍须实测成功率。

## 2. 这次改变解决什么

| 已观察的失败 | 新流程中的处理 | 剩余限制 |
|---|---|---|
| 不知道手臂后面衣服的形状，补画掩码漏区域 | 从完整的躯干模板开始，躯干先画完，肩甲/手臂随后叠上 | 隐藏衣纹是重新设计，需检查合理性 |
| 肩甲同时进入躯干和手臂 | 部件规范固定归属；袖口/肩甲随对应手臂；躯干绘制要求排除它们 | 程序不理解画面中的假肩甲，仍须语义复核 |
| 后腿多出另一条大腿 | 单腿完整轮廓由模板提供，其他部件没有输出区域 | 轮廓内仍可能画错，不能仅靠 alpha 判完整 |
| 头变成放大头像 | 局部绘制画布映射到已知的头部位置与尺寸 | 头发边缘、脸形和画风仍需审核 |
| 自动姿势点把手腕放错 | 绑定关节由模板在绘制前定义 | 模板比例可能不适合某角色，须先审核适配 |
| 返回图看着完整，受限合成却缺衣服 | 部件先有完整几何和覆盖合同，生成前能检查覆盖 | 有覆盖不等于颜色/纹理/解剖正确 |

不能把普通的生成模型描述为严格遵守关节、轮廓或遮罩。程序只确定最终坐标、透明度和允许写入范围，AI 内容必须审核。当前图像工具没有可传原生二值掩码的接口，本路线可用局部登记板和软件合成实现；不能宣称调用了不存在的严格蒙版 API。

## 3. 每个角色的具体过程

### A. 身份与适配稿

自动记录脸/发型、配色、服装标志、装备和原图不可见处；选用预先验收的体型/服装模板。首批只做两种通用比例，不对单图手修骨长或轮廓。模板比例和简化过的组装草稿先给用户看；超出范围且无法保留重要设计时停止。

输出：来源记录、身份说明、模板 ID、适配清单。原始附件字节不可用时明确记载，生成代理图不能冒充原图。

### B. 程序建立完整部件合同

每个模板包含骨长、关节、完整闭合躯干轮廓、两条独立完整手臂、两条独立完整腿、头/髋/武器区域、手部握点、层级以及材料分区。继续导出当前 puppet 能读取的槽位；不重写动作系统。

每个部件区分：必须覆盖的结构区域、允许变化的轮廓边缘、禁止出现的区域、用于挂接的重叠区域。隐藏根部从一开始存在。完整部件间的挂接重叠是合法的；肩甲被画两份是语义错误，不能把两者混为一谈。

绘制前输出部件分色图和关节叠加图，检查连通性、结构覆盖和挂接。发现缺口先修模板或模板生成规则，不先花生图次数。模板只包含几何和材料布局，最终脸、服装纹理、装饰与线稿由 AI 绘制。

### C. AI 按部件绘制，程序组装

先完成无手臂遮挡的躯干，再绘制四肢和头，最后处理剑。每个请求采用同一版本的角色设计说明、配色、固定模板登记板和部件提示词。局部图可放大绘制，导出位置由程序从合同映射，不要求 AI 把小头像留在全身图顶部。

躯干请求只包含完整躯干的指令与引导；手臂单独有肩—肘—腕—手和衣袖/皮肤分区；腿单独有髋—膝—踝—脚。近侧和远侧分别绘制，不能直接镜像明显不对称装备。

程序采用已知部件区域处理 alpha、映射坐标，保留源返回图和裁切诊断。不允许用轮廓强裁把错位的手指、靴尖或衣边削掉后当通过；不允许把返回图背景当作不透明身体来填满模板。边缘溢出、内容偏位、灰底混入和明显错画要拒绝。

固定 alpha 可以保证部件占据规定的结构区域，不能保证 AI 在其中画对了手、肌肉或衣褶。头发与手指等细轮廓需单独审核，不能用通用椭圆或胶囊的像素覆盖冒充合格美术。实际工具若不能在这些条件下稳定产出，试验应判失败。

输出：完整 PNG 图层、程序生成的关节/握点数据、登记与合成报告、全部原始生成结果。提示词和约束按版本存档，具体角色只填身份描述与受支持模板参数。

### D. 静态与动态验收

静态至少看四种图：每层单独显示、全身组装、关节放大、移开手臂/腿后的暴露区域。移开肢体能看到的躯干和腿根必须完整；待机全身图不能替代这个检查。

使用已知模板关节建立 rig，并接入现有数值校验和导出。不能继续用自动姿势识别覆盖已知关节；不能通过跳过检查让新入口通过。已知模板的绑定入口需要新增适配，现有 `layer_parts.py` 的图片推断流程不会自动支持它。

先做受控的关节活动检查，再导出 idle/walk。肩、肘、髋、膝的检查角度由支持的动作范围确定，不能为一张图缩小到刚好看不出缺口。检查摆臂是否完整、衣纹是否拉扯、接口是否露缝、是否有额外肢体/武器、脚是否滑步。用户看过走路效果后才扩大动作范围。

所有结构缺陷保持 blocker；修改像素后须重审实际问题，不能直接把 resolved 改 true。报告分别记录结构校验、数值 QA、视觉复核和用户验收，禁止合并成一个含混的 pass。

## 4. 实施顺序与停止条件

1. **先做三个部件的技术试验。** 躯干、一条完整手臂、一条腿，优先验证无漏补、无轮廓硬裁、风格能匹配。头/手的细节也必须在进入全角色前验证。每个部件最多3次实际生成，共用持久计数；到限则本轮路线验证失败，不换目录继续抽图。
2. **再做两个不同体型的真实 AI 美术角色。** 第一位用当前剑客已获认可的简化设计，第二位用不同体型/配色的受支持角色。相同模板规则与代码，不加入角色名字特判、不手画掩码、不为单图调整 QA 阈值。单角色成功只能记为单例成功。
3. **两个角色均通过完整图层、暴露检查和 idle/walk 后，才试接默认入口。** 发布前继续用独立样本统计首次成功率、限额内成功率、平均生成次数和失败类型。两例不能证明商用稳定，尚未取得的数据不编造目标达成。
4. 若受限模板仍无法在限额内产出合格美术，结论应是自动美术制作未达到要求；保留当前可靠的“完整分层素材输入→绑定/动画”能力。不能再声称任意单图可稳定自动交付。逐角色美术修整不符合本项目现行约束，不能偷偷作为兜底。

这轮要检验的是能否产出合格素材，而不仅是失败有没有被拦住。几何故障注入和两个合成体型测试只验证程序约束，不算真实美术成功。

## 5. 代码改动边界

- 新增独立的模板合同与登记板生成模块；测试先覆盖两种比例、故障轮廓、遗漏覆盖及合法挂接重叠。
- 新增按部件接收图片、检查、组装和生成已知关节 rig 的入口；输出复用现有 puppet 数据格式及 `write_binding`，不重写动作。
- 给工作流增加模板 ID、合同哈希、生成计数、各阶段审核失效规则；各部件提示词仍集中管理。
- `dev/masked_completion.py` 继续作为旧分割实验的边界证据，不直接升级为该新路线；20%局部补画目标也不拿来评价从完整模板绘制的新部件。旧失败结论保持不变。
- 只有真实图片验收通过，才更新默认 skill、同步和打包。现在仅形成设计，不提前标“已支持”。
